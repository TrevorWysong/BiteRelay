# Languages

Relay's app speaks the language its person reads. The approach is small, typed and dependency-free (`web/src/i18n`).

- **English is the source** (`en.ts`): every message has a key, such as `"nav.orders"`.
- **Each translation is a catalog of the same keys** (`es.ts`), typed against English, so a missing key fails the typecheck.
- **`test/i18n.test.ts` checks the rest:** every placeholder matches, and every plural has the forms its language needs.
- **A message** is a string with `{name}` placeholders. When it counts something, it's plural forms keyed by `Intl.PluralRules` category (`one`, `other`, and `zero`/`two`/`few`/`many` where a language has them), with the number as `{count}`.
- **In a component:** `const t = useT();` then `t("appeal.awarded", { amount: formatCents(award) })`. Outside React, use `t(...)`.
- **The language** is the device's best match (`negotiate`: an exact tag, then the language alone, "es-MX" → "es"), or the person's choice in Profile → Language. Their choice is kept on the device.
- **Loading:** catalogs other than English load on demand, before the first render that needs them (main.tsx awaits the person's language at startup). No screen waits on one.
- **Numbers, money and dates follow the same locale** (`appLocale()` in lib/format.ts). Distances use miles or kilometres by the device's region.

## Adding a language

1. Copy `es.ts` to `<tag>.ts`, translate every message, and give each plural the forms its language needs.
2. List it in `LOCALES` and `loaders` (`i18n/index.ts`), and in the test's `catalogs`.

## Writing UI

New copy goes through `t()`: add the English to `en.ts` and the translation to every catalog. Don't build sentences from fragments. Give the translator the whole sentence with placeholders, because word order differs between languages.

## Where extraction stands

Every screen people use is translated, along with the library code that writes words (order statuses, cancellation reasons, opening hours, notifications, ledger entries and so on).

The policies page is translated whole, one document per language (`lib/policies/en.ts`, `es.ts`). A test holds every language to English's sections, points, effects and risks under any network's settings.

These stay English on purpose:
- dev-only screens: the local-node fields, identity switching and the dev reset hints;
- the brand name;
- card brand names.

`node web/scripts/i18n-report.mjs` lists anything inline that's crept back.

Messages from the network itself, such as a zome refusing a call, are English. They're the network's words, not the app's. A screen that shows one to people should map the refusals it expects to messages of its own.
